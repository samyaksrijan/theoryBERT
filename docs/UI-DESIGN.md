# TheoryBERT React product

The 24 October 2026 redesign replaces the primary Streamlit workflow with a locally served React product. The Python formal core, model architecture, training tools, independent checkers and Manim boundary remain in use.

## Pages and primary tasks

| Route | Purpose |
|---|---|
| `/` | Reference-inspired public landing: horizontal navigation, bold editorial hero, pink discovery accents, animated diagonal showcase, example search/filter/sort, studio entry points and recent work. |
| `/dfa` | Description/reference editor, explicit prediction source, verified DFA canvas, trace playback, state inspection, evidence and video export. |
| `/grammar` | Grammar/token editor, independent tree verification, ambiguity selection, production-by-production playback and node inspection. |
| `/examples` | Searchable and filterable example library. DFA previews use the actual reference machines; opening a card loads its inputs into the relevant studio. |
| `/research` | Measured baseline results, honest experiment status, model architecture and executed training/environment checks. |

Workspace settings use an accessible native dialog. They hold checkpoint path, candidate budget, parse-tree limit and video quality. Reference JSON stays close to the DFA task that needs it.

## Design system

- **Public landing:** the supplied Dribbble screenshot informs composition rather than content. White, near-black `#0D0C22`, pink `#E84B89`, a soft pink introduction banner, pill controls and generous spacing replace the former dashboard overview. The large diagonal showcase uses code-native illustrations of actual shipped languages. Search, category filters, topic chips, sorting, the learning-mode switch, gallery links and the mobile menu are functional. There are no invented accounts, reviews or social metrics. Landing styles are scoped to `.landing` in `frontend/src/landing.css`; `Landing.jsx` owns this route.
- **Surfaces:** white panels and navigation, near-white `#FBFAFC` workspace, subtle dotted diagram canvases and thin lavender-gray borders.
- **Navigation and actions:** near-black `#0D0C22` text and primary buttons; pink `#E84B89` discovery accents and pale pink active navigation. Darker pink `#D03676` gives small canvas highlights sufficient contrast. The landing, footer, workspace and favicon share one Poppins brand asset. `Brand.jsx` consumes checked-in outline data generated by `scripts/build_wordmark.py`, so the logo and intro do not depend on font loading. The standalone vector is `frontend/public/theorybert-logo.svg`; the Poppins license is included.
- **Typography:** DM Sans for headings and interface text, IBM Plex Mono for symbols/code/technical labels, and an outlined Poppins 700/600 wordmark with BERT above the letter-spaced THEORY. Fonts are served locally. Manim uses the included DM Sans and IBM Plex Mono TrueType assets, with a fallback if the frontend assets are absent.
- **State palette:** rose, violet, teal and related muted hues. State tags, SVG nodes, tables and Manim share the same indexed palette. The active node retains its state's assigned color in both the canvas and video; the active-state legend follows it. Transition and symbol highlights use the common rose accent. Accepting states have double rings, so their meaning does not depend on color.
- **Outcomes:** green for passed verification, amber for missing references/resource conditions, and red for rejected candidates/errors. Every outcome also has text and an icon.
- **Motion:** short page transitions, state/edge changes, step highlights and subtle reference-diagram motion. Reduced-motion preferences are respected. Playback advances a previously checked trace, not an independently inferred simulation.

Tokens live in `frontend/src/tokens.css`. Component/layout styling is in `styles.css`, the typography/contrast pass is in `readability.css`, and the shared landing-to-workspace treatments are in `workspace-theme.css`. Canvas geometry, layout and interaction controls are preserved. SVG geometry comes from the shared Python layout functions.

## Startup sequence

A fresh load of `/` displays the Poppins logo writing itself on a blank white screen. Letters draw, fill with ink, and settle before a 400 ms fade reveals the landing page (2.35 seconds total). The page mounts behind the intro, with interaction/accessibility access gated until reveal. Skip and Escape dismiss it; body scrolling is restored. The intro does not replay during normal client navigation and does not delay direct studio URLs. Reduced-motion preferences bypass it. `brand.css` styles the wordmark and startup sequence.

## Interaction boundaries

Inputs and results persist locally in browser storage. Editing a verification input marks the result as outdated, locks playback/export and removes old videos from the current flow. Changing only export quality retains verification. Selected ambiguous trees survive navigation.

The canvas supports play/pause, previous/next steps, restart, speed selection, a keyboard-operable range input, zoom, pan and an expanded view. State/node buttons expose descriptive accessible labels. Evidence tabs support arrow keys, Home and End. Dialogs trap focus; hidden mobile navigation is inert. Icon-only buttons have explicit accessible names.

The React client receives JSON for display. The Python server retains the actual `VerifiedDFA` or verified tree evidence and rechecks it before Manim rendering. A client-supplied result identifier cannot substitute arbitrary Python, a raw DFA, or a forged verification seal. Result handles are bounded and process-local: after an engine restart, an expired video-export request asks the user to verify again.

## Validation commands

```sh
python scripts/run_local.py
# In another terminal:
python -m pytest -q
python scripts/check_web_api.py
python scripts/inspect_react.py
```

`check_web_api.py` exercises real HTTP jobs, accepted and rejected inputs, missing references/checkpoints, deliberately failed candidates, strict JSON handling, CFG ambiguity/epsilon, larger-machine drawing limits, actual DFA/CFG video exports, byte-range playback, and direct page refreshes.

`inspect_react.py` uses an isolated Chromium test context. It checks navigation, interaction, keyboard controls, settings, invalidation, mathematical failure states, real video playback and responsive layouts, and saves screenshots/report data under `artifacts/react-ui/`. Native Chrome inspection also exercised verified DFA playback and video playback. No hosted deployment is part of this local-only workflow.

`python scripts/inspect_brand.py` validates normal intro playback, automatic reveal, Skip/Escape, focus after Skip, navigation without replay, direct studio access, reduced motion, and desktop/mobile layout. Screenshot stages and the report are under `artifacts/brand-ui/`.
